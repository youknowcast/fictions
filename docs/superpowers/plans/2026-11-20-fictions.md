# fictions Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 受け取った動画・音声を、サンドボックス内の ffmpeg で QuickTime 再生可能な mp4/m4a に正規化する Rust 製 CLI。

**Architecture:** 単一バイナリ。ffmpeg/ffprobe は外部コマンドとして呼び、`sandbox-exec`（Linux は `bwrap`）で包む。処理は「グループ検出 → プローブ → 出力仕様決定 → 1パスエンコード → 検証 → アトミック rename」の直列パイプライン。各段は純粋関数として切り出し、ffmpeg を呼ぶ層だけを薄く保つ。

**Tech Stack:** Rust 1.99（mise 管理）、clap(derive)、anyhow、serde/serde_json、blake3、tempfile。テストは `cargo test` と、ffmpeg でフィクスチャを生成する統合テスト。

**Spec:** `docs/superpowers/specs/2026-11-20-fictions-design.md`

## Global Constraints

- 解像度は変更しない。`scale=trunc(iw/2)*2:trunc(ih/2)*2` と `setsar=1` のみ。
- H.264: profile high / yuv420p / `-crf 21 -preset medium`、コンテナ mp4。
- HEVC: `-tag:v hvc1` / `-crf 23 -preset medium`、8bit は main、10bit は main10。
- 音声: AAC-LC、48kHz、1ch 64k / 2ch 160k / 6ch 384k / それ以外 64k×ch（上限 512k）。
- `-movflags +faststart`。
- 出力名: `<ベース名の先頭50文字>-<hash8>.<mp4|m4a>`。50 はバイトではなく文字数。
- 終了コード: 0 成功またはスキップ、1 失敗、2 引数エラー。
- 人間向けメッセージは stderr、結果のパスだけ stdout。
- ffmpeg は必ず `Command` の配列引数で呼ぶ。シェルを介さない。
- 入力ファイルは削除も変更もしない。
- ffmpeg 9 系を想定（`-fps_mode`、`-progress pipe:1` が使える）。最低 6.0。

## Review Focus

- 0 バイト／メディアでない入力 → panic せず exit 1。
- 出力先ディレクトリが書き込み不可 → 明確なメッセージで exit 1。
- 日本語・絵文字を含む 50 文字境界のファイル名 → 文字境界で切る。
- パーツ間で音声あり／なしが混在 → 無音を挿して連結し、失敗しない。
- 切り詰められた入力 → 出力は残すが exit 1。

- [ ] **Step 2: 失敗を確認**

Run: `cargo test group -q` → FAIL

- [ ] **Step 3: 実装**

`strip_index`: 最後の `" ("` を `rfind` し、`)` で終わり、中身が全部 ASCII 数字のときだけ `Some((head, n))`（`n` は `u32` パース失敗なら `None`）。head は空でないこと。

`detect_group`:
1. `input` の stem を取る。`strip_index(stem)` が `Some((cand, _))` かつ同ディレクトリに `cand` + 同じ拡張子のファイルが在れば、`base = cand`。無ければ `base = stem`。
2. ディレクトリを読み、同じ拡張子で「stem が `base` と完全一致」または「`strip_index(stem) == Some((base, _))`」のものを集める。
3. 並びは `order` 昇順、`None` を先頭（キーは `order.map_or((0, 0), |n| (1, n))`）。同じ番号が複数あればパス文字列順。
4. 各ファイルを `std::fs::read` して `blake3::hash` を取り `digest` に入れる。同じ digest が既に出ていれば `dropped` に積んで除外。
5. `hash8` は全パーツの digest を順に `blake3::Hasher` に食わせ、`to_hex()` の先頭10文字のうち先頭8文字。

- [ ] **Step 3: 実装**

規則:
1. 全パーツに映像が無ければ音声のみ（`Container::M4a`、`video: None`）。
2. 映像があれば `height = max`、`width = max`（同じ高さで幅が違う場合は大きい方）、偶数に丸め（`& !1`）。
3. HDR が混在、または bit_depth が混在 → `anyhow::bail!`（メッセージに `--no-group` を案内）。
4. `hdr || height > 1080` → HEVC。`caps.libx265 == false` なら H.264 にフォールバックし警告を1本積む。
5. pix_fmt: H.264 は `yuv420p`。HEVC は 10bit なら `yuv420p10le`、そうでなければ `yuv420p`。
6. crf: H.264 21、HEVC 23。
7. 音声チャンネル: 全パーツ同じならその値、違えば 2。6ch 超は 6。無音パーツは無視する。
8. ビットレート: 1ch 64、2ch 160、6ch 384、それ以外 `min(64 * channels, 512)`。サンプルレートは常に 48000。
9. fps はパーツが 2 本以上のときだけ `Some(最大の平均フレームレート)`。

## 手動確認（macOS）

Linux の CI では `sandbox-exec` を検証できないため、Mac で以下を1回行う。

1. `cargo run -- <mp4>` が `sandbox-exec` 込みで成功する。
2. `sandbox-exec` のプロファイルが ffmpeg の起動を妨げない（妨げる場合は `process-exec` の literal に対象を追加）。
3. 出力を QuickTime で開き、映像・音声・縦横比が正しい。
4. `foo.mp4` + `foo (1).mp4` を連結した出力が QuickTime でシームレスに再生される。
