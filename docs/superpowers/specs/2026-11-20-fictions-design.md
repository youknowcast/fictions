# fictions — 受け取ったメディアをローカル再生用に正規化する CLI

## 意図

人から渡された動画・音声を、ローカルで再生する前に一度通すための道具。
目的は二つあり、優先順位はこの順。

1. **無害化**: 入力のパースは必ず ffmpeg が行うので「変換したから安全」とは言えない。
   危険なのはむしろ、受け取ったファイルをそのまま再生環境（QuickTime など）に
   食わせること。fictions は ffmpeg を隔離して走らせ、出力を狭い許可リストの
   コンテナ／コーデックに落とすことで、再生時の攻撃面を小さくする。
2. **ダイエットと再生互換**: QuickTime で開けないファイルを開けるようにし、
   無駄に太ったファイルを痩せさせる。解像度は勝手に変えない。

## 利用シーン

- 相手から mp4 が1本届く。`fictions ~/Downloads/foo.mp4` を叩く。同じ場所に
  `foo-<hash>.mp4` ができ、それを QuickTime で開く。
- 同じ名前で複数回落ちてきた `foo.mp4`, `foo (1).mp4`, `foo (2).mp4` は
  1本の動画の分割パーツなので、1本に連結される。
- まとめて処理したいときは shell 側で `for f in ...; do fictions "$f"; done`。

## ゴール

- 引数1個で動く。設定ファイルなし。`brew install ffmpeg` 以外の前提なし。
- 入力は書き換えない。出力は入力と同じディレクトリに、内容由来の名前で置く。
- 出力は macOS の QuickTime で確実に再生できる。
- ffmpeg はサンドボックス内で動く。
- 出力が壊れていないことを、成功と報告する前に検証する。
- macOS で動く。Linux でも動く（動作確認用）。

## 非ゴール

- HDR のトーンマッピング。HDR 入力は HDR のまま HEVC で通す。
- 副音声・字幕・チャプター・添付ファイルの保持。先頭の映像1本と音声1本だけ残す。
- アップスケール。入力より大きい解像度にはしない。
- 複数ファイルの並列処理やバッチモード。
- URL 入力、DRM、画像シーケンス、ライブストリーム。
- 変換の再開（レジューム）。

## アンチゴール（こうなったら失敗）

- QuickTime で開けないファイルが出る。
- 入力より容量が増えるのに、そうと知らされない。
- 途中で失敗したのに、成功したように見える半端なファイルが残る。
- 「無害化」と言いながら、ffmpeg がネットワークにもファイルシステムにも自由に触れる。

## 決定事項（ユーザーが決めたこと）

| 論点 | 決定 |
| --- | --- |
| 実行環境 | macOS が主。Linux は動作確認用 |
| 実装 | Rust、単一バイナリ。ffmpeg は外部コマンドとして呼ぶ |
| 入力の単位 | 1回の実行で1本（連結対象のグループを1本と数える） |
| 出力先 | 入力と同じディレクトリ |
| 出力名 | 元ファイル名の先頭50字 + ハッシュ |
| 連結 | `foo.mp4`, `foo (1).mp4`, … を macOS 既定の命名順で連結 |
| 再生先 | QuickTime 優先。だめなら mpv |
| 解像度 | 無理にリサイズしない。4K は 4K のまま |
| 容量 | 再エンコードで痩せさせる。4K は HEVC を許す |
| 音声のみの入力 | 対応する |
| 隔離 | sandbox 実行を入れる |

## 私の判断（実装前に確認してほしい点）

1. **ハッシュは入力内容の BLAKE3**（全パーツのバイト列を順に食わせた先頭8桁）。
   出力内容のハッシュにすると、同じ入力でも実行のたびに別名になり重複が増える。
   入力由来なら再実行は「同じ名前が既にある → スキップ」で冪等になる。
2. **出力名は `<50字に切り詰めたベース名>-<hash8>.<ext>`**。ベース名は ` (n)` を
   落としたもの。切り詰めはバイトではなく文字数で行う。
3. **完全に同一内容のパーツは連結しない**（バイト一致を検出して1本に畳む）。
   ` (1)` が分割パーツではなく重複ダウンロードだった場合の保険。
4. **音声は常に再エンコード**（AAC-LC、48kHz）。コピーでは壊れたパケットが
   そのまま残るため。チャンネル数は保つ（モノラル／ステレオ／5.1）。
5. **同一グループ内で解像度が揃っていない場合は、最大のものに合わせて
   レターボックス**（拡大はしない。小さい方は黒帯で埋める）。
6. **失敗時は一時ファイルを残して場所を報告する**。成功時は消す。
7. **入力のデコードでエラーが出たら、出力は残したまま失敗（exit 1）として報告する**
   （途中で切れたダウンロードなど）。`ffmpeg -v error` の stderr が空でなければ
   疑わしいとみなす。再生はできるかもしれないが、保証はしない。

## パイプライン

```
引数 → グループ検出 → 入力プローブ → 出力仕様決定 → サンドボックス内でエンコード
     → 出力プローブ＋全デコード検証 → アトミックにリネーム → 結果報告
```

### 1. グループ検出

- 入力パスの stem から末尾の ` (\d+)` を落とした名前を候補ベースとする。ただし、
  **その候補ベースのファイルが同じディレクトリに実在するときだけ**ベースとして採用する。
  これにより `Movie (1982).mp4` の年が消えない（`Movie` が無ければ `Movie (1982)` が
  ベース）。`foo (1).mp4` だけが手元にある場合も、`foo` が無いので単独ファイル扱い。
- 同じディレクトリで、同じ拡張子かつ `^<base>( \(\d+\))?$` に一致するファイルを集める。
- 並び順: ベース（番号なし）→ `(1)` → `(2)` → … の数値昇順。
  文字列比較ではなく数値比較（`(10)` は `(2)` の後）。
- 集まったパーツのバイト列を順に BLAKE3 に食わせ、`hash8` を得る。
- 完全一致するパーツが複数あれば、最初の1本だけ残して残りを警告付きで除外する。
- パーツが1本だけなら通常の単一処理。

### 2. プローブ（ffprobe, JSON）

ffprobe もサンドボックス内で走らせる。読むのは以下だけ。

- 映像ストリームの有無、width/height、SAR、pix_fmt、bit depth、field_order、回転行列、色空間（HDR 判定）
- 音声ストリームの有無、channels、sample_rate
- コンテナの duration
- 既定ストリーム（disposition default）の優先順位

### 3. 出力仕様決定

| 入力 | 映像 | コンテナ |
| --- | --- | --- |
| 映像あり・高さ ≤1080 かつ SDR | H.264 High / yuv420p | mp4 |
| 映像あり・高さ >1080 または HDR | HEVC Main（8bit）/ Main10（10bit）、`-tag:v hvc1` | mp4 |
| 音声のみ | なし | m4a（AAC-LC） |

仕様は**グループ全体で1つ**決める。パーツ間で HDR/SDR や bit depth が混在する場合は
正当な出力が存在しない（SDR を HDR として tag すれば色が壊れ、逆はトーンマッピングで
非ゴール）。この場合はエラーで止め、`--no-group` でパーツごとに処理するよう案内する。
解像度が混在する場合は最大に合わせ、小さいパーツを黒帯で埋める（拡大しない）。

音声は、パーツ間でチャンネル構成が揃っていればそのまま。混在時はステレオに揃える
（モノラルは複製で無害、5.1 はダウンミックスになるため警告する）。6ch を超える
構成（7.1 など）は 5.1 に落とす。ビットレートは 1ch 64k / 2ch 160k / 6ch 384k、
それ以外は 1ch あたり 64k（上限 512k）。

- 解像度は入力のまま。`scale=trunc(iw/2)*2:trunc(ih/2)*2` で偶数に丸め、
  `setsar=1` で pixel aspect を 1:1 に直す（QuickTime の縦横比ずれ対策）。
- 回転メタデータはピクセルに焼き込んでから捨てる（ffmpeg の autorotate に任せる）。
- インターレース入力は `yadif` でプログレッシブにする。
- 10bit を H.264 に落とす場合は yuv420p へ（H.264 の QuickTime 再生を優先）。
- HDR 入力は解像度に関わらず HEVC にする（H.264 に落とすと色が壊れる）。
- 品質: x264 `-crf 21 -preset medium`、x265 `-crf 23 -preset medium`。
  上限ビットレートは設けない（CRF に任せる）。
- 音声: `-c:a aac -ar 48000`、ビットレートはチャンネル数で 64k/160k/384k。
- `-movflags +faststart`。

### 4. エンコード

- 単一パーツ: そのまま1回エンコード。
- 複数パーツ: `-filter_complex` の `concat` で1パスにまとめる。各パーツは
  出力仕様に正規化（スケール／パディング／fps／SAR／音声リサンプル）してから
  連結する。パーツ単位の一時ファイルは作らない（二重エンコードを避ける）。
- 音声を持たないパーツには `anullsrc` を足して本数を揃える。
- fps は concat 時のみ、パーツ間で最大の平均フレームレートに CFR で揃える。
- 進捗は `-progress pipe:1` を読んで stderr に出す（TTY のときだけ）。
- 出力は同じディレクトリの `.fictions-tmp-<pid>/` に書き、検証後に rename。

### 5. サンドボックス

macOS は `sandbox-exec -f <profile>` で ffmpeg / ffprobe を包む。プロファイルは
実行時に生成する。骨子:

```
(version 1)
(deny default)
(allow process-exec)                  ; 対象バイナリ自身のみに絞る
(allow file-read* (subpath "/usr") (subpath "/System") (subpath "/Library")
                  (subpath "/opt/homebrew") (subpath "/private/tmp")
                  (literal "<入力ファイル1>") ...)
(allow file-write* (subpath "<一時ディレクトリ>"))
(allow sysctl-read)
(deny network*)
```

- ネットワークは全面的に不可。
- 書き込みは一時ディレクトリのみ。最終ファイルは fictions 側が rename する。
- 読み取りはシステム領域と入力ファイルに限定（細工されたプレイリストで
  他のファイルを読ませる経路を塞ぐ）。
- `sandbox-exec` は deprecated だが macOS 15 でも動作する。無い環境では
  **黙って外さず失敗**し、`--no-sandbox` を案内する。
- Linux は `bwrap --unshare-all --ro-bind / / --bind <tmp> <tmp>` を使う。macOS ほど
  読み取りを絞らず、ファイルシステム全体を読み取り専用で見せる（Linux は動作確認用の
  位置づけで、守るべき脅威は macOS 側にある）。無ければ同じく失敗し `--no-sandbox` を案内する。
- ffmpeg には `-protocol_whitelist file` を渡す。

### 6. ffmpeg の検査とキャッシュ

毎回 `ffmpeg -version` を叩くのは無駄なので、結果を使い回す。

- キャッシュ: `~/Library/Caches/fictions/ffmpeg.json`（Linux は `$XDG_CACHE_HOME/fictions/`）。
- 無効化: ffmpeg の実パス・mtime・サイズのどれかが変わったとき、または前回検査から
  7日経ったとき（`brew upgrade` を拾うため）。
- 検査内容: バージョン、`libx264` / `libx265` / `aac` の有無、使うフィルタ
  （`scale`, `setsar`, `yadif`, `concat`）の有無。
- 判定:
  - 必須の機能が欠けている → **失敗**。`brew upgrade ffmpeg` を案内する。
  - バージョンが想定より古い、または `libx265` が無い → **警告して続行**。
    `libx265` が無い状態で 4K/HDR が来たら H.264 にフォールバックし、
    容量が増えうることを警告する。
  - 問題なし → 何も出さない。
- 検査はサンドボックス外で行う（入力ファイルを読まないため）。初回だけ数十ms。

### 7. 検証

成功と報告する前に、出力に対して必ず行う。

- ffprobe: 期待したストリームがある、pix_fmt が許可リスト内、縦横が偶数、
  SAR が 1:1、duration が入力合計と ±1秒以内。
- `ffmpeg -v error -i out -f null -` を最後まで流し、終了コード0かつ stderr 空。
- エンコード中の stderr も `-v error` で収集する。中身があれば、出力の検証に通っても
  **exit 1**（出力は残す）。入力の破損を成功として隠さないため。
- どれか落ちたら失敗扱い。一時ファイルは残してパスを出す。

### 8. 出力名と衝突

- `<base の先頭50文字>-<hash8>.<mp4|m4a>`
- 既に同名ファイルがあれば、エンコードせずスキップ（終了コード0、メッセージ表示）。
  `--force` で上書き。
- 入力ファイルは決して削除・変更しない。

## CLI

```
fictions <input>            # 変換して出力パスを表示
fictions --force <input>    # 既存出力を上書き
fictions --dry-run <input>  # グループ・出力名・仕様だけ表示
fictions --no-sandbox <input>
fictions --no-group <input>   # 連結せず、そのファイルだけ処理
fictions --quiet <input>
```

- 終了コード: 0 成功またはスキップ、1 失敗、2 引数エラー。
- 人間向けメッセージは stderr、結果のパスだけ stdout。

## Rust 構成

- crates: `anyhow`, `clap`(derive), `serde`/`serde_json`, `blake3`, `tempfile`
- モジュール: `cli` / `probe` / `group`(検出・並び・重複排除) / `naming` / `spec`(出力仕様決定)
  / `encode`(ffmpeg コマンド組み立て) / `concat` / `sandbox` / `verify`
- ffmpeg / ffprobe は PATH から探す。無ければ `brew install ffmpeg` を案内して終了。
- ffmpeg の呼び出しは `Command` で組み立て、引数は必ず配列で渡す（シェルを介さない）。

## テスト

- 単体: 命名の切り詰め（日本語・絵文字を含む50文字境界）、グループ検出と自然順、
  重複パーツの畳み込み、出力仕様の決定表、サンドボックスプロファイル生成（ゴールデン）。
- 統合: テスト内で ffmpeg を使い 1〜2 秒のフィクスチャを生成して実行。
  - 単一 mp4 → 期待どおりのストリーム・解像度・SAR
  - 3分割パーツ → 連結後の duration が合計と一致
  - 音声のみ → m4a
  - 壊れた入力 → 失敗し、成功を報告しない
  - 再実行 → スキップ
- Linux の CI で統合テスト。macOS は手元で sandbox 込みの確認。

## リスク

- `sandbox-exec` は非推奨。将来消える可能性がある。消えたら `--no-sandbox` を
  明示しない限り動かない（安全側に倒す）。
- 4K HEVC の再エンコードは遅い。10分の 4K で数十分かかりうる。進捗表示は必須。
- HDR の QuickTime 再生は Apple Silicon 前提。Intel Mac では色が浅く見えることがある。
- 連結は「同じ動画の分割パーツ」という前提。無関係な同名ファイルを連結すると
  意味不明な出力になる。重複検出はその一部しか救えない。
